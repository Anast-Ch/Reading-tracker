# API — Reading Tracker

Базовый URL (локально): `http://localhost:8000`
Интерактивная документация (Swagger): `http://localhost:8000/docs`

## Общие правила

- Формат обмена — JSON (UTF-8), кроме загрузки файлов (`multipart/form-data`).
- Все эндпоинты, кроме `/auth/*`, `/health` и `/static/*`, требуют заголовок
  `Authorization: Bearer <access_token>`. Токен действует 24 часа.
- Даты передаются как `YYYY-MM-DD`. Время создания и изменения — UTC
  в формате ISO 8601 с суффиксом `Z`.
- Коды ошибок:

| Код | Когда |
|-----|-------|
| 400 | нарушено бизнес-правило: статус/даты/оценка, занятый email, неверный текущий пароль, неподходящий файл обложки, несогласованные параметры статистики |
| 401 | нет токена, токен неверный или просрочен; неверный email или пароль при входе |
| 404 | книга (или издание) не найдены, книга принадлежит другому пользователю |
| 422 | неверный формат данных: тип, длина, диапазон, нет обязательного поля |
| 503 | внешний сервис поиска (FantLab) недоступен |

- Ошибки 400, 401, 404, 503 приходят в виде `{"detail": "текст"}`.
  При 422 поле `detail` содержит список ошибок по полям.

### Примеры ошибок

`400`:

```json
{ "detail": "Для статуса «Прочитано» нужна дата завершения" }
```

`401`:

```json
{ "detail": "Не удалось подтвердить авторизацию" }
```

`404`:

```json
{ "detail": "Книга не найдена" }
```

`422` — в `loc` указано поле с ошибкой:

```json
{
  "detail": [
    {
      "type": "string_too_short",
      "loc": ["body", "title"],
      "msg": "String should have at least 1 character",
      "input": ""
    }
  ]
}
```

`503`:

```json
{ "detail": "Сервис поиска недоступен, введите книгу вручную" }
```

## Служебное

### GET /health

Проверка работы сервера. Токен не нужен. Ответ `200`:

```json
{ "status": "ok" }
```

## Аутентификация

### POST /auth/register

Регистрация. Пароль — от 8 символов, не более 72 байт в UTF-8
(латиница — 1 байт на символ, кириллица — 2). Токен в ответе не возвращается:
после регистрации нужно вызвать `POST /auth/login`.

Запрос:

```json
{ "email": "user@example.com", "password": "string" }
```

Ответ `201`:

```json
{ "id": 1, "email": "user@example.com", "name": null }
```

Ошибки: `400` — email уже занят; `422` — неверный формат email, длина пароля.

### POST /auth/login

Вход. Возвращает JWT-токен.

Запрос:

```json
{ "email": "user@example.com", "password": "string" }
```

Ответ `200`:

```json
{ "access_token": "jwt...", "token_type": "bearer" }
```

Ошибки: `401` — неверный email или пароль; `422`.

Отдельного эндпоинта выхода нет: выход — это удаление токена на клиенте.
Восстановления пароля нет.

## Профиль

### GET /users/me

Данные текущего пользователя. Ответ `200`:

```json
{ "id": 1, "email": "user@example.com", "name": "Анна" }
```

`name` равно `null`, пока имя не задано. Ошибки: `401`.

### PATCH /users/me

Изменение имени и/или email. Передаются только изменяемые поля.

```json
{ "name": "Анна", "email": "new@example.com" }
```

- `name` — строка от 1 до 150 символов (пробелы по краям обрезаются)
  или `null`, чтобы сбросить имя;
- `email` — корректный адрес, `null` запрещён;
- токен после смены email остаётся действительным;
- пустое тело `{}` допустимо и ничего не меняет.

Ответ `200` — обновлённый объект пользователя.
Ошибки: `400` — email занят другим пользователем; `401`; `422`.

### PATCH /users/me/password

Смена пароля.

```json
{ "current_password": "старый", "new_password": "новый_пароль" }
```

`new_password` подчиняется тем же правилам, что и при регистрации
(от 8 символов, не более 72 байт).

Ответ `204` без тела. Ошибки: `400` — неверный текущий пароль (не `401`,
чтобы клиент не выбрасывал пользователя на экран входа); `401`; `422`.

### DELETE /users/me

Удаление аккаунта вместе со всеми книгами и файлами обложек. Необратимо.
Ответ `204` без тела. Ошибки: `401`.

## Книги

Одна запись — одно прочтение. Одну и ту же книгу можно добавить несколько раз
(перечитывание), проверки на дубликаты нет.

### Объект книги

```json
{
  "id": 1,
  "title": "Мастер и Маргарита",
  "author": "Михаил Булгаков",
  "publish_year": 2020,
  "status": "read",
  "start_date": "2025-04-01",
  "finish_date": "2025-04-20",
  "rating": 5,
  "pages_count": 480,
  "cover_path": null,
  "created_at": "2026-01-10T12:00:00Z",
  "updated_at": "2026-01-10T12:00:00Z"
}
```

| Поле | Тип | Ограничения |
|------|-----|-------------|
| title | string | обязательное, 1–500 символов |
| author | string | обязательное, 1–300 символов |
| publish_year | int / null | 1–9999 |
| status | string | `want_to_read`, `reading`, `read` |
| start_date | date / null | не в будущем |
| finish_date | date / null | не в будущем, не раньше start_date |
| rating | int / null | 1–5 |
| pages_count | int / null | от 1 до 100000 |
| cover_path | string / null | только для чтения, меняется через эндпоинты обложек |

Пробелы по краям `title` и `author` обрезаются.

### Правила статуса, дат и оценки

| Статус | start_date | finish_date | rating |
|--------|------------|-------------|--------|
| `want_to_read` | должна быть null | должна быть null | должна быть null |
| `reading` | необязательна | должна быть null | должна быть null |
| `read` | необязательна | **обязательна** | необязательна |

Нарушение правил — `400`. Сервер ничего не обнуляет сам: при смене статуса
клиент отправляет `null` в лишние поля.

| Новый статус | Что отправить в PATCH |
|--------------|-----------------------|
| `want_to_read` | `status`, `start_date: null`, `finish_date: null`, `rating: null` |
| `reading` | `status`, `finish_date: null`, `rating: null`; `start_date` по желанию |
| `read` | `status`, `finish_date` (обязательно); `start_date` и `rating` по желанию |

Даты «не в будущем» сервер проверяет по своей текущей дате, поэтому выбор даты
в интерфейсе лучше ограничить сегодняшним днём.

### POST /books

Создание книги. Обязательные поля: `title`, `author`, `status`.

Ответ `201` — объект книги. Ошибки: `400`, `401`, `422`.

### GET /books

Список книг текущего пользователя (без пагинации).

Параметры:

- `status` — `want_to_read`, `reading` или `read` (необязательный);
- `year` — год даты завершения, только вместе с `status=read`;
  без `status=read` — `400`.

Порядок фиксирован и не настраивается:

- `want_to_read`, `reading` и запрос без `status` — по дате добавления,
  сначала новые;
- `read` — по дате завершения, сначала новые.

При равенстве — по `id`, сначала новые. Ответ `200` — массив объектов книги
(пустой, если книг нет). Ошибки: `400`, `401`, `422` (неверное значение
`status` или `year`).

### GET /books/counts

Количество книг по спискам. Все три ключа есть всегда.

```json
{ "want_to_read": 3, "reading": 1, "read": 12 }
```

### GET /books/years

Годы, в которых есть прочитанные книги (по дате завершения), по убыванию.
Если прочитанных нет — `[]`.

```json
[2026, 2025, 2024]
```

### GET /books/{id}

Одна книга. Ответ `200` — объект книги. Ошибки: `401`, `404`.

### PATCH /books/{id}

Частичное изменение. Передаются только изменяемые поля. Можно менять
`title`, `author`, `publish_year`, `status`, `start_date`, `finish_date`,
`rating`, `pages_count`. Поля `id`, `user_id`, `created_at`, `updated_at`,
`cover_path` через PATCH не меняются.

- Правила проверяются по **итоговому** состоянию книги (старые значения
  плюс присланные).
- `null` запрещён для `title`, `author`, `status` (`422`).
- Пустое тело `{}` допустимо и ничего не меняет.

Пример — перевод из «Прочитано» в «Читаю»:

```json
{ "status": "reading", "finish_date": null, "rating": null }
```

Ответ `200` — обновлённый объект. Ошибки: `400`, `401`, `404`, `422`.

### DELETE /books/{id}

Удаление книги вместе с файлом обложки. Ответ `204` без тела.
Ошибки: `401`, `404`.

## Обложки

Обложка хранится на сервере. В объекте книги поле `cover_path` содержит путь
вида `/static/covers/3f2a....jpg`; полный адрес картинки — адрес сервера плюс
`cover_path`. Если обложки нет, `cover_path` равен `null`.

### POST /books/{id}/cover

Загрузка или замена обложки. Запрос — `multipart/form-data`, поле `file`.

- форматы: JPG, PNG, WEBP; размер до 2 МБ;
- формат определяется по содержимому файла, а не по имени или расширению;
- если обложка уже есть, она заменяется, старый файл удаляется.

Ответ `200` — объект книги с новым `cover_path`.
Ошибки: `400` — файл не изображение, недопустимый формат или больше 2 МБ;
`401`; `404`; `422` — не передано поле `file`.

### DELETE /books/{id}/cover

Удаление обложки. Ответ `200` — объект книги с `cover_path: null`.
Если обложки не было, ответ тот же. Ошибки: `401`, `404`.

### POST /books/{id}/cover/from-fantlab

Установка обложки по номеру издания из поиска FantLab. Сервер сам скачивает
картинку с fantlab.ru (другие адреса не принимаются), проверяет её теми же
правилами, что и загруженный файл, и сохраняет. Замена существующей обложки
разрешена.

```json
{ "edition_id": 12345 }
```

Ответ `200` — объект книги с новым `cover_path`.
Ошибки: `400` — у издания нет картинки или она не прошла проверку;
`401`; `404` — книга не найдена; `422`; `503` — FantLab недоступен.
При любой ошибке книга остаётся с прежней обложкой.

### Статические файлы

`GET /static/covers/<имя файла>` — отдаёт картинку, авторизация не нужна.
Имена файлов случайные (UUID), адрес нельзя угадать.

## Поиск книг (FantLab)

Подсказки при вводе названия берутся из каталога FantLab. Сервер обращается к
FantLab сам, клиент к нему напрямую не ходит. Результаты поиска не сохраняются:
выбранная книга создаётся обычным `POST /books`, а обложка добавляется отдельным
запросом `POST /books/{id}/cover/from-fantlab`.

### GET /search/books

Поиск произведений. Параметры:

- `q` — строка поиска, 3–200 символов (обязательный);
- `page` — номер страницы, от 1, по умолчанию 1.

Ответ `200`:

```json
{
  "items": [
    {
      "title": "Мастер и Маргарита",
      "author": "Михаил Булгаков",
      "work_type": "роман",
      "work_year": 1967,
      "edition_id": 12345,
      "cover_url": "https://fantlab.ru/images/editions/big/12345"
    }
  ],
  "page": 1,
  "has_more": false
}
```

| Поле | Описание |
|------|----------|
| title | название произведения |
| author | автор или авторы одной строкой |
| work_type | тип произведения (роман, повесть, сборник и т. п.) |
| work_year | год первой публикации произведения, `null` если неизвестен; это **не** год издания, в `publish_year` его подставлять не нужно |
| edition_id | номер издания с обложкой, `null` если обложки нет |
| cover_url | адрес картинки для предпросмотра, `null` если `edition_id` равен `null` |

В выдаче только книжные произведения (без рецензий, статей, интервью и т. п.).
Если ничего не найдено, `items` пустой. Ошибки: `401`, `422`, `503`.

### GET /search/editions/{edition_id}

Данные издания: страницы и год издания. Используются, чтобы подставить их в
форму после выбора варианта из подсказок.

Ответ `200`:

```json
{ "pages_count": 480, "publish_year": 2020 }
```

Любое из полей равно `null`, если в каталоге оно не указано.
Ошибки: `401`; `404` — издание не найдено; `503`.

## Статистика

### GET /stats

Статистика прочитанных книг за период. Учитываются книги со статусом `read`;
период определяется по дате завершения (`finish_date`).

Параметры:

| Параметр | Описание |
|----------|----------|
| period | `month`, `year` или `season` (обязательный) |
| year | год, 1900–2100 (обязательный) |
| month | номер месяца 1–12; обязателен при `period=month`, иначе не передаётся |
| season | `winter`, `spring`, `summer`, `autumn`; обязателен при `period=season`, иначе не передаётся |

Сезоны:

| Сезон | Месяцы |
|-------|--------|
| winter | декабрь **предыдущего** года, январь и февраль года `year` |
| spring | март — май года `year` |
| summer | июнь — август года `year` |
| autumn | сентябрь — ноябрь года `year` |

Зима года Y — это декабрь Y−1, январь Y и февраль Y, поэтому сумма четырёх
сезонов не равна значению за год.

Ответ `200`:

```json
{
  "period": "season",
  "year": 2026,
  "month": null,
  "season": "winter",
  "count_read": 4,
  "average_rating": 4.25
}
```

- `count_read` — число прочитанных книг за период;
- `average_rating` — среднее по книгам, у которых указана оценка, число с
  двумя знаками после запятой; `null`, если оценок нет;
- в пустом периоде `count_read` равно `0`, `average_rating` равно `null`;
- `month` и `season` в ответе равны `null`, если не относятся к периоду.

Ошибки: `400` — параметры не согласованы (нет `month` при `period=month`,
нет `season` при `period=season`, лишний `month` или `season`);
`401`; `422` — неверное значение или тип параметра.
